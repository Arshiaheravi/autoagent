## 0. Executive Summary

AutoAgent V2 is a working autonomous loop that has shipped 426+ sessions and ~3,479 cultivOS tests' worth of code. **It is functional but carries significant risk debt.**

The five most consequential findings, in priority order:

1. **Leaked secrets in git history** — Telegram bot token + GitHub PAT are committed to `master`. Documented in backlog as "Seb action" since 2026-04-03; still unrotated.
2. **15 duplicate `" 2.py"` files in `engine/`** — silent dead code from finder/sync collisions. Several have parallel `test_* 2.py` files that may run twice and inflate the test count.
3. **`council.py` is 871 lines and has no direct test file** — only mocked in `test_director_brain.py`. Largest single module in the repo, untested at the unit level.
4. **Prompt-surface confusion** — root-level `PROJECT.md` / `NORTH_STAR.md` describe **cultivOS**, while `.autoagent/PROJECT.md` describes **the AutoAgent framework**, and `.autoagent/NORTH_STAR.md` describes **cultivOS**. PROMPT.md instructs the agent to read `autoagent/PROJECT.md` — ambiguous which copy wins.
5. **Cost-tracking duplication** — `daily_budget.json` accrues real spend; `sessions.json` records 267 entries with `cost_usd: 0` for all of them. Source of truth is unclear and the dashboard reads the wrong one for any non-Max-plan run.

Spend is currently ~$26–34/day (cap $40), well inside budget. No incident in flight. Code is shippable today; the audit is about reducing future-incident probability.

### 2a. Self-misconfig (audit step 9)

Two pairs of `PROJECT.md` / `NORTH_STAR.md` exist in this repo:
- The **root pair** (gitignored, per `.gitignore` lines 4–10) describes cultivOS.
- The **`.autoagent/` pair** (also gitignored) is a mix: `PROJECT.md` says "AutoAgent Agency", `NORTH_STAR.md` says cultivOS.

PROMPT.md tells the agent to read `autoagent/PROJECT.md` — relative to which CWD? `engine/run.py` line 41 resolves it as `AGENT_DIR / "PROJECT.md"` (i.e. `.autoagent/PROJECT.md`), but the bootstrap prompt sent to Claude (`run.py` line 141) uses the bare string `autoagent/PROJECT.md`, which Claude interprets relative to its CWD (the project root) — and **that file does not exist** in V2 (only `.autoagent/PROJECT.md` and `/PROJECT.md` exist).

**Root cause:** PROMPT.md was written for a directory layout (`autoagent/`) that no longer exists. V2 renamed it to `.autoagent/` but the prompt template was not updated.

**Fix:** rewrite the bootstrap prompt in `engine/run.py` lines 139–150 to use `.autoagent/PROJECT.md` consistently, and rewrite PROMPT.md to match. Delete the root-level `PROJECT.md` / `NORTH_STAR.md` (or move them to a `cultivos.example/` directory if they document the target). One commit. (Effort: S, Quality: M.)

### 2b. PROMPT.md rule-bloat

323 lines, 14 numbered top-level sections, ~30 sub-rules. Notable bloat indicators:

- **6 distinct sources cited** (arxiv 2603.13723, arxiv 2603.05344, arxiv 2602.00164, etc.) — half are speculative future-dated arxiv IDs (2603 = March 2026; some don't resolve). Past-dated provenance for instructions Claude actually has to follow degrades trust in the rule set.
- Section "STAGED COMPACTION" (lines 63–67) and "ATTENTION RECITATION" (line 75) prescribe internal cognitive operations that Claude does not literally control — they're aspirational, not enforceable.
- The "WHAT 'DONE' MEANS" checklist (lines 313–323) duplicates the "AFTER COMPLETING ANY TASK" gate (lines 169–222) almost line-for-line.
- "BACKWARDS-COMPATIBLE DICT ACCESS" (line 90) and "MODULE SPLITTING" (line 93) are *patterns* that belong in a skill file, not the master prompt.

**Recommendation:** trim PROMPT.md to ≤180 lines by (a) deleting arxiv citations, (b) collapsing the two end-of-task checklists into one, (c) moving pattern-rules to skills. (Effort: M, Quality: L — directly reduces every-session input tokens and instruction fade-out.)

## 4. Launcher + run.py

### 4a. Launcher subprocess injection surface — `launcher.py:92`

```python
cmd = f'cat "{tmp}" | "{CLAUDE_CMD}" --print --dangerously-skip-permissions --max-turns 30'
result = subprocess.run(cmd, shell=True, ..., env=env, cwd=str(ROOT))
```

`shell=True` is used. Inputs are:
- `tmp` — `tempfile.NamedTemporaryFile`, OS-generated path, no user input. Safe.
- `CLAUDE_CMD` — `shutil.which("claude")` or hardcoded fallback. Safe under default `$PATH`; an attacker who can write to `$PATH` already wins.

**Verdict:** not exploitable today. But the pattern is fragile — if `CLAUDE_CMD` ever grows a configurable source (env var, JSON config), this line becomes injectable. Replace with `subprocess.run([CLAUDE_CMD, "--print", ...], stdin=open(tmp), ...)` — list args, no shell. (Effort: S, Quality: S.)

### 4b. Self-healing scope — `launcher.py:54–110`

The healer:
- Calls Claude CLI with `--max-turns 30` and a 600-second timeout.
- Loops up to `MAX_RETRIES = 5`.
- Treats "no FIXED/COULD_NOT_FIX signal but some output" as success (line 102–104).

**Risk:** the lenient "assume fixed" branch at line 104 means a Claude session that produces *any* output — even an apology that the bug is unfixable — counts as a fix. Combined with 5 retries, that's up to 5 unsupervised Opus calls per crash. At ~$0.50–$2 per call, a single bad crash can spend $5–10 unattended.

**Recommendation:** require the literal `FIXED` token; treat ambiguous output as failure. Add per-day healer-cost cap. (Effort: S, Quality: M.)

### 4c. run.py session-type routing — `run.py:89–93`

```python
if session_num % 20 == 0: return "deep"
if session_num % 10 == 0: return "brain"
if session_num % 5  == 0: return "meta"
return "work"
```

Simple modular schedule. Distribution: 14 work / 4 meta / 1 brain / 1 deep per 20 sessions. Matches CLAUDE.md description. Safe.

### 4d. Cost accounting — `run.py:79–86`, `198–203`

`log_cost(usd)` writes to `daily_budget.json` only when the `cost_usd` field comes back >0. On Max-plan CLI runs, the field is 0 — so `daily_budget.json` reflects only API-mode runs. Yet `daily_budget.json` shows ~$26–34/day spend across the last three days. Either:
- Recent runs were API-mode (override active), or
- The `cost_usd` field is being populated even on the Max plan (recent CLI versions do report token cost).

`sessions.json` (267 entries) carries `cost_usd: 0` for every entry — so dashboard analytics that read sessions.json **understate spend by 100%**. This is the duplication called out in §0.

**Recommendation:** unify on a single source. Either (a) write per-session cost into `sessions.json` from the same `cost` value `log_cost` consumes, or (b) delete the `cost_usd` key from `sessions.json` and have the dashboard read `daily_budget.json`. (Effort: S, Quality: M.)

## 5. Cost Controls

**Config (`config.json`):**
```
model:               claude-opus-4-7
daily_limit_usd:     40.0
session_max_seconds: 1800
session_max_turns:   50
interval_hours:      0
```

**Actual spend (`daily_budget.json`):**
```
2026-04-14: $34.33
2026-04-15: $26.16
2026-04-16: $26.39  (still climbing — afternoon of audit day)
```

- **Interval = 0** means the loop runs back-to-back with only the 60-second cooldown at `run.py:354`. With `tasks_limit` set the cooldown is skipped entirely.
- **Per-session cap of 1800s + 50 turns** is reasonable. `run.py:170` enforces wall-time correctly.
- **Daily cap of $40 is honored**: `run.py:325` checks `budget_ok()` before each session and sleeps an hour if over.

**Gaps:**
- No per-session $ cap; only turns and seconds. A single Opus turn that ingests a 200K-token context can cost $1+. 50 turns × $1 = $50 — over the daily cap from one session.
- No alert on near-cap. `daily_budget.json` is silent until the hard stop.
- Healer calls (§4b) are **outside** the budget check — they spawn separate Claude processes that don't go through `run_session`.

**RedHunter-incident posture:** the original incident was a runaway autonomous loop. Today's controls catch it at the daily level but not the per-session level. Add `session_max_usd` to config and trip the wall-time logic if exceeded. (Effort: S, Quality: L.)

## 6. Council + Advisor Architecture

### 6a. council.py — live or dead?

**Live.** `engine/director_brain.py:59` does `from council import convene_council`; it is the entry point for free-text questions to the director. `engine/director_helpers.py:196–198` exposes a `/council` shell command. Two integration tests (`test_integration.py:346, 368`) patch `council._call_codex` and `council._call_<...>`, so council is exercised — but only through mocks.

**Risk:** 871 lines of LLM orchestration with **zero direct unit tests** (`test_council.py` does not exist). Any refactor to council's prompt or model routing has no safety net.

### 6b. Advisor pattern — adopted?

**No.** `grep` for `advisor_20260301`, `advisor-tool`, `betas=`, `tools=[{"type": "advisor` returns zero hits across the entire repo. The pattern is documented in global `~/.claude/CLAUDE.md` as the default for new agents but has not been retrofitted into council.py or director_brain.py.

This is the single highest-leverage architectural change available. Council currently spawns multiple full Opus sessions in parallel for each question (3 + chairman = 4 Opus calls minimum); the advisor pattern would let a Sonnet executor consult Opus only at decision points, cutting per-call cost ~3–5×.

**Recommendation:** keep council.py as-is for the user-facing `/council` command (the multi-perspective output is the feature). For the autonomous loop's brain/meta sessions, migrate to advisor pattern. (Effort: L, Quality: L — biggest single cost win.)

### 6c. Model routing correctness

`config.json` pins `claude-opus-4-7` for **every** session type — work, meta, brain, deep. Sonnet is never used. Per global CLAUDE.md, Sonnet should be the default for execution; Opus only for deliberation. Current setup overspends ~3× on the WORK sessions that make up 70%+ of all sessions.

**Recommendation:** add `models.work = sonnet`, `models.meta = opus`, `models.brain = opus` to config; route in `run.py:161`. (Effort: S, Quality: L.)
